# Cortetsu 2.0 — integración nativa de F1b–F9

Esta entrega sustituye el runtime Python propio y conecta instalador, owners
Rust, coordinador Go y QML. Es un cambio del código publicado en `main`; no
instala ni recarga el escritorio del portátil. La fase anterior permanece en
[el registro histórico](../history/MIGRATION-PROTOTYPES-2026-10-22.md).

| Bloque | Resultado implementado | Verificación reproducible |
| --- | --- | --- |
| F1b — IPC y ejecución | Contratos estrictos compartidos, sesión/epoch/UID, operaciones tipadas, CAS, idempotencia durable, deadlines y cancelación | Rust rescue, Go execv1/ipcv1/execclient, integración entre procesos |
| F2 — CLI y generaciones | Plataforma Rust; schema 2 adoptado por el instalador; helpers y recursos fijados; recuperación y rollback conjunto | Platform/rescue, dos instalaciones aisladas, corrupción y fallo posterior a activación |
| F3 — dominio transaccional | DND compartido por CLI, QML y Go; journal, readback, recuperación y prioridad de cambios manuales | Owner Rust, intercalados de historial, fixture Quickshell con D-Bus privado |
| F4 — coordinador | Instancia por sesión, Hyprland y D-Bus nativos, reconexión y pérdida de owner explícita | AF_UNIX privado, D-Bus privado, dos sesiones, detector de carreras |
| F5 — migración de helpers | Equivalentes Rust para todos los entrypoints inventariados y transformaciones del instalador | Contratos nativos y referencias Python congeladas, paletas y planner |
| F6 — políticas | Catálogo, prioridad, histéresis, cooldown, TTL, auditoría y ejecución verificada | Motor puro más runner con owner real; consentimiento y override manual |
| F7 — QML | Un bridge, negociación/reconexión, Settings de automatización y readback autoritativo | Modelos JS, Qt Quick Test, fixture real de procesos/socket |
| F8 — activación | Consentimiento por dominio y sesión; pausa, desactivación y revocación explícita del propietario previo | Activación durable, CAS del propietario, UI y runner |
| F9 — Python propio | Cero rutas Python y cero invocaciones de intérprete en el runtime nuevo | Inventario Go con `--require-native`, hashes de oráculos y PATH sin Python |

El contrato operativo y las rutas de código/pruebas están en
[NATIVE-RUNTIME.md](NATIVE-RUNTIME.md). Los checks de GitHub Actions del SHA
concreto son la evidencia del resultado de CI; esta tabla describe las piezas
entregadas y no sustituye esos checks.

## Alcance de aceptación

- **F1b–F9:** implementación nativa integrada e instalable, con gates de nube.
- **F10:** la QA física de las nuevas piezas en el HP Victus AMD/NVIDIA sigue
  sin ejecutarse en esta entrega: HDMI/hotplug, suspensión, gaming, consumo,
  latencia y convivencia con la sesión gráfica real requieren ese equipo.
- **F11:** publicación de una release final y aceptación física se mantienen
  separadas. No se crea un tag de release ni se cambia el sistema del usuario.

**Estado del código: `NATIVE_RUNTIME_IN_MAIN`. Estado del portátil:
`UNCHANGED`. Automatizaciones: `DISABLED_UNTIL_EXPLICIT_DOMAIN_CONSENT`.**
