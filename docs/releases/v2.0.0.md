# Cortetsu 2.0.0 — Runtime nativo

**Cortetsu 2.0** transforma los dotfiles de CachyOS/Arch en un entorno de escritorio versionado, verificable y reversible. La interfaz sigue siendo **Hyprland + Wayland + Quickshell/Qt 6**, pero ahora se apoya en servicios nativos **Rust**, un coordinador de políticas **Go** y una plataforma de instalación transaccional. El runtime instalado ya no necesita Python.

Esta es la primera publicación estable de la arquitectura Cortetsu 2.0. Mantiene su identidad visual propia —sumi, acero ennegrecido, índigo, bermellón, superficies translúcidas y animaciones cuidadas— y conserva control explícito sobre la configuración, los procesos y los recursos del equipo.

## Novedades principales

### 1. Arquitectura Rust + Go + QML

- **Rust como propietario de operaciones de sistema:** configuración, verificación, recuperación, teclado, monitores, hardware, sensores, energía, GameMode, fondos, calendario, Pomodoro, notificaciones y utilidades del escritorio.
- **Go como coordinador por sesión:** observación de Hyprland y D-Bus, normalización de eventos, reglas, resolución de conflictos, reconexiones y aplicación verificada de políticas.
- **Interfaz Qt 6/QML con un bridge compartido:** comunicación IPC versionada, estado autoritativo y recuperación explícita ante desconexiones.
- **Runtime sin Python:** los 28 puntos de entrada nativos conservan sus nombres; las implementaciones Python anteriores permanecen exclusivamente como referencias históricas y oráculos de pruebas.
- **Ejecución tipada:** contratos `cortetsu.exec/1`, argumentos validados, revisión esperada (CAS), idempotencia durable, plazos y cancelación. El IPC no acepta comandos arbitrarios del shell.

### 2. Instalación transaccional y rollback completo

Cortetsu gestiona cuatro capas coordinadas: **shell**, **dotfiles**, **helpers nativos** y **generación de sistema**.

- Manifiestos `SYSTEM.json` (schema 2), `FILES.json` y `HELPERS.json` con integridad SHA-256.
- Promoción con locks y journals recuperables (`PREPARED`, `ACTIVE`, `COMMITTED` y `RECOVERED`).
- Copias de seguridad previas a la adopción de archivos, verificación de rutas y protección frente a alteraciones de generaciones.
- `cortetsu verify` y `cortetsu-rescue verify` independientes de la interfaz; `cortetsu recover` y `cortetsu rollback` recuperan el conjunto de capas, no solo el shell.
- Checkpoints históricos y *pins* para proteger generaciones; `cortetsu gc` muestra primero un plan, requiere un `PLAN_ID` vigente y permite archivar antes de eliminar.
- La instalación **no recarga Quickshell ni inicia o reinicia `cortetsu-power-auto`**: adoptar la nueva interfaz y cambiar el daemon de energía siguen siendo decisiones explícitas.
- El constructor compila el **shell completo en Quickshell real antes de sellarlo**, evitando publicar generaciones con errores QML de compilación que las pruebas unitarias aisladas no detectaban.

### 3. Experiencia de escritorio

- **Bottom Hub**, dock y taskbar contextuales por monitor, con control de bandeja, estados y animaciones.
- **Overview** con vistas de ventanas y espacios de trabajo.
- **Portapapeles** integrado con Clipse, navegación y acciones de contenido.
- **Hardware Center** para recursos, sensores, perfiles energéticos, procesos, pantallas y diagnóstico.
- Nueva página **Sistema**: modelo, SKU, placa, BIOS, sistema operativo, CPU, memoria, GPU, monitores y opción «Copiar información».
- **Fn+Esc** abre directamente Sistema; **OMEN** mantiene su acceso a Hardware Center; **Super+H** permanece disponible. Los controles evitan duplicados y respetan el modo de pantalla completa.
- Editor de **atajos y teclados**, captura de combinaciones, acciones por tecla y compatibilidad con gestos.
- **Display Manager** con topologías y operaciones con comprobación, persistencia y rollback.
- Gestor orbital de **fondos de pantalla**, paletas dinámicas y sincronización de Kitty mediante archivo mutable externo a las generaciones selladas.
- **Calendario** y **Pomodoro** persistente con descansos, notificaciones y recuperación precisa al reanudar.
- Centro de **notificaciones**, DND transaccional, controles multimedia y OSD coherentes entre monitores.

### 4. Automatización bajo control del usuario

El coordinador Go puede observar el escritorio sin tomar decisiones por el usuario. Los dominios `notifications`, `gamemode`, `power` y `display` requieren **consentimiento explícito por sesión**.

Las reglas incluyen prioridad, histéresis, cooldown, caducidad, readback y trazabilidad. Las modificaciones manuales tienen preferencia; una pérdida de owner o reconexión no se interpreta como autorización para aplicar cambios. No se activan automáticamente políticas por instalar Cortetsu.

## Rendimiento y estabilidad

Se priorizaron cambios medibles y sin degradación visual:

- **8 ventanas Layer Shell innecesarias menos** con grosor de borde 0: en la configuración probada de dos monitores se pasó de 20 a 12 superficies y se eliminaron aproximadamente **31–37 hilos**. El ahorro exacto de PSS no se extrapola de una sola muestra.
- El **wallpaper** se decodifica a la resolución de la pantalla; una medición comparable mostró unos **40 MiB menos**.
- Quickshell en reposo con dos monitores se midió alrededor de **0,16–0,22 % de un hilo lógico** en el HP Victus utilizado para QA. El 1,2 % observado en una generación anterior dejó de reproducirse tras los ajustes de actualización del reloj.
- Desaparece el sondeo de **20 Hz** de `cortetsu-power-auto`; el coordinador Go evita consultas duplicadas al estado de Hyprland.
- El temporizador nativo de Pomodoro usa un reloj adecuado para suspensión y procesa inmediatamente una fase vencida al reanudar.
- Servicios y animaciones opcionales se activan según su uso; los paneles ocultos no deben mantener trabajo gráfico periódico innecesario.
- La arquitectura híbrida **AMD/NVIDIA** se respeta sin forzar la GPU dedicada para todas las aplicaciones.

*Las cifras de rendimiento corresponden al equipo y a las condiciones especificadas en los informes de QA; no representan un requisito ni una promesa universal de consumo.*

## Correcciones destacadas

- **Compilación QML integral:** corregida una propiedad duplicada de `ClipboardItem.qml` que impedía cargar una generación completa; nueva puerta de compilación previa a instalación.
- **Detección de fullscreen y foco:** compatibilidad con Hyprland 0.56 en modo Lua, corrigiendo Fn+Esc, OMEN, selección de monitor para brillo y políticas de inactividad.
- **Notificaciones:** corrección de tiempos de caducidad predeterminados y en fullscreen; limpieza del historial sin bucles de bindings.
- **Wi-Fi y Bluetooth:** corregido un binding reactivo circular; ajustadas las rutas nativas de operación y errores.
- **Reglas de capa:** reemplazo de referencias `caelestia-*` obsoletas por coincidencias efectivas de superficies Cortetsu.
- **Temperatura:** el dashboard muestra el sensor real de CPU y no una zona térmica ACPI arbitraria.
- **Calendario:** navegación por teclado, distinción visual entre «hoy» y selección, y fechas acordes con el idioma.
- **Accesibilidad:** nombres y valores de deslizadores, mejora del contraste de texto secundario y coherencia de foco.
- **Localización:** traducción de cadenas heredadas del portapapeles y de Display Manager.
- **Lanzador:** acciones de modo claro/oscuro no disponibles quedan deshabilitadas y explicadas, en vez de fallar silenciosamente.
- **Gestión segura de procesos:** `cortetsu shell adopt` deja de terminar instancias de Quickshell ajenas al runtime Cortetsu.
- **Ciclo de vida energético:** instalar no interrumpe ni reaplica perfiles del daemon activo; `SIGTERM` termina normalmente para systemd y `SIGINT` conserva su semántica.
- **CLI:** la salida de `cortetsu generations` maneja limpiamente el cierre de tubería (`EPIPE`), por ejemplo al utilizar `head`.
- **Tema Kitty:** los colores vivos se escriben de forma atómica fuera de las generaciones inmutables, sin invalidar sus hashes.

## Instalación y actualización

**Plataforma objetivo:** CachyOS/Arch Linux con Hyprland, Wayland, Quickshell y Qt 6. Las dependencias se definen en `packages/arch.toml` y se inspeccionan con `doctor`; Cortetsu no instala paquetes del sistema automáticamente.

Para obtener exactamente esta versión desde fuentes:

```bash
git clone --branch v2.0.0 https://github.com/DilanRC/Cortetsu.git
cd Cortetsu
scripts/cortetsu doctor
scripts/cortetsu install
scripts/cortetsu verify
```

Para una instalación existente y supervisada por systemd, adoptar la nueva interfaz es una operación independiente:

```bash
cortetsu shell reload
cortetsu verify
cortetsu-rescue verify
```

Adoptar el daemon energético nuevo también requiere una acción explícita cuando corresponda; la instalación no cambia por sí sola el perfil activo.

### Recuperación

```bash
cortetsu generations
cortetsu-rescue verify
cortetsu rollback
cortetsu verify
```

No elimines las generaciones `previous` ni los checkpoints protegidos sin revisar un plan de GC. Una instalación inicial debe seguir el procedimiento del README y el perfil correspondiente, en lugar de asumir que un shell supervisado ya existe.

**Distribución:** publicación del código fuente etiquetado; esta release no incluye paquetes binarios precompilados ni instaladores universales.
