## Decisión de implementación

- Usar el flujo de protocolos Wayland virtuales como contrato de entrada y captura. Nunca crear un canal de entrada desde dispositivos físicos del anfitrión.
- Adoptar patrones verificables de lifecycle, XDG, D-Bus, entorno sanitizado, supervisión, limpieza, logs y selección explícita de AMD cuando aporten una frontera real.
- Mantener el observador como proceso separado del compositor para que cerrar o reiniciar la observación no controle el ciclo de vida del realm.
- Mantener la CLI/MCP independiente de proveedor. No copiar módulos, scripts ni tests de las cuatro referencias.
- La revisión estática se complementó con una ejecución aislada en `evidence/hypr-computer/live-probe/`. `scripts/probe-hypr-computer.sh` comprueba el HEAD revisado, crea un realm efímero sobre el workspace read-only, ejecuta la prueba y conserva la evidencia antes de limpiar el realm.

## Prueba live de `hypr-computer`

- Entorno: HEAD `cd00962d7faf3a5059827994fbe746783695787f`, realm padre `hypr-computer-probe-426052` y compositor anidado `agent-realm-hypr-computer-probe`. El fixture sustituyó solo `agentdesk._instances()` por lectura de los `hyprland.lock` del `XDG_RUNTIME_DIR` privado; no invocó `hyprctl instances` sin selección. Las consultas IPC y la ventana del visor apuntaron a firmas del realm padre o anidado, nunca a la sesión anfitriona.
- El compositor anidado publicó `wayland-2` y su firma resolvió al socket privado correspondiente. El padre usó `wayland-1`. Ambos sockets coincidieron con sus firmas. La consulta de monitores y la ventana GTK `hypr-computer test` confirmaron Hyprland anidado real y una aplicación independiente.
- `wayland-info` observó `wl_seat` con capacidad `pointer`. `AgentInput` escribió exactamente `HYPR_COMPUTER_PRIVATE_INPUT`; el fixture registró click, arrastre de `dx=60, dy=50` y scroll de la lista hasta `value=114.6`.
- La ventana del visor se enfocó en el realm padre mientras la ventana activa del compositor anidado conservó el mismo título y dirección antes y durante la observación. Seis capturas del visor durante 2.9 s cambiaron entre cada par (fracción de píxeles distinta: 0.0008–0.0016); seis capturas Wayland directas con buffer reutilizado y seis con buffer nuevo también cambiaron. La captura directa del escritorio cambió 8.1 %. No se reprodujo congelamiento con el diálogo de actualización de Hyprland descartado. Ese diálogo tapa la lista y el reloj del fixture, por eso el ensayo lo cierra por entrada virtual antes de medir.
- El contrato del visor falla: el `close-request` ejecuta `agentdesk.stop()`. Cerrar la ventana terminó el compositor anidado (`desk_alive_after_viewer_close=false`), así que la sesión no permanece utilizable después de cerrar el visor. El script sale con código 1 y `acceptance_passed=false` para que el fallo no aparezca como éxito.
- Esta prueba demuestra que el backend nested, entrada, foco, screencopy y visor pueden ejecutarse bajo esta configuración; no acepta `hypr-computer` como arquitectura debido al acoplamiento entre el cierre del observador y el ciclo de vida. Su ruta predeterminada de descubrimiento del host tampoco es adecuada para este ensayo y se evitó en el fixture.
